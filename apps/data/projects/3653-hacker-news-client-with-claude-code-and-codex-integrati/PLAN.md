# Hacker News Client with Claude Code and Codex Integration

## Tech Stack

- **Tauri** as the desktop runtime, because the surface is a cross-platform desktop app and Tauri ships small, native binaries that match the post's "desktop app" claim.
- **Rust** for the Tauri backend, because Tauri requires it and the work is local I/O plus subprocess management.
- **TypeScript with React** for the in-app UI, because the surface is a list-and-detail layout with a chat pane and React fits the shape.
- **Hacker News API (Firebase)** as the data source, because it is the public, official path to posts and comments.
- **Claude Code CLI and Codex CLI** as the chat runners, invoked as subprocesses, so the user's existing credentials and subscription are the runtime.
- **SQLite** for the local store of fetched posts and rundowns, because Tauri ships SQLite bindings and the user's data should live on the user's disk.
- **No deploy target beyond the desktop binaries** — the app is distributed as installable bundles per platform.

## Architecture

The user pastes a Hacker News post URL or ID into the app. The Rust backend fetches the post and its comments from the HN Firebase API up to a stated comment-depth budget, normalises the data into a thread tree, and stores it in a local SQLite database so the user can return to it later.

The rundown is generated by sending the normalised thread to whichever runner the user has selected (Claude Code CLI or Codex CLI) as a subprocess. The runner returns a structured rundown, and the app pairs each bit with the source comment ID so the UI can hyperlink back to the specific HN comment.

The chat surface uses the same runner. A user message is sent to the selected CLI with the post or the entire thread as context, and the response is rendered in the chat pane. The local store caches rundowns and chat transcripts so the user does not re-fetch or re-generate on every open.

## Milestones

1. **M1 — Tauri shell** — the cross-platform desktop bundles for macOS, Windows and Linux.
2. **M2 — HN fetch** — pull a post and its comments by URL or ID up to a stated depth.
3. **M3 — Citation design** — pair every rundown bit with the source comment ID for hyperlinking.
4. **M4 — Runner integration** — subprocess invocation of Claude Code CLI and Codex CLI with the thread as context.
5. **M5 — Chat surface** — the chat pane that routes through the selected runner.
6. **M6 — Local store** — the SQLite cache of fetched posts, rundowns and chat transcripts.
7. **M7 — Settings** — the small surface for choosing the default runner and model.

## Risks

- **Citation precision** — a rundown whose hyperlinks resolve to the wrong comment ID breaks the product's main claim; the pairing must be exact.
- **Comment depth budget** — a runaway tree walk that exhausts tokens or stalls the UI is a real failure mode.
- **Runner availability** — neither Claude Code nor Codex may be installed; the UI must surface that clearly.
- **Runner drift** — both CLIs change their CLI surface; the integration must be resilient to version changes.
- **Local store drift** — the cached thread can diverge from the live HN thread if HN edits or deletes a comment; the cache age should be visible.
- **Cross-platform bundling** — Tauri ships for macOS, Windows and Linux, but the dev-loop and signing requirements differ per platform.
