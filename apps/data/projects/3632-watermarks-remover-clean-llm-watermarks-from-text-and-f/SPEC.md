# Watermarks Remover: Clean LLM watermarks from text and files

## Problem

The capture names three different families of provenance mark that ride along on files you create: invisible Unicode characters, C2PA / EXIF / XMP metadata blocks, and statistical text watermarks produced by LLM providers. The source's own description — quoted verbatim — is that the project is an "Open-source agent skill + stdlib HTTP service that strips invisible Unicode, C2PA/EXIF/XMP, and (best-effort) statistical text marks from files you own." The four watermark families it names explicitly are Claude, Gemini-SynthID, OpenAI, Kirchenbauer and the keyed-Gumbel class, which is the realistic surface area for a text-watermark remover in 2026.

The author draws an explicit line inside that sentence. The first two families — invisible Unicode and the metadata blocks — are deterministic and well-understood, and any honest tool can claim to remove them. The third family — statistical text marks — is described by the author with the qualifier "best-effort", which is the right framing because text watermarks work by perturbing token probabilities in a way that survives paraphrase and even partial rewriting, and no public tool can promise total removal against a well-funded detector. The plan treats that qualifier as load-bearing and reproduces it everywhere the statistical class is named.

The "files you own" framing in the source matters too. The tool is positioned as acting on files the user controls, not as a service that removes provenance marks from arbitrary third-party content. That positions the project as a self-defence and portability tool for creators who do not want their text re-identifiable as AI-generated by a third-party detector, and as a metadata-stripper for images and documents the user is publishing under their own name. It does not position the tool as a way to launder provenance from material where the provenance is not the user's to remove, and the plan does not soften that constraint into a "neutral utility" framing.

What the source does not name is also part of the honest reading. There is no list of supported file formats, no removal-rate benchmark, no model-side trade-off discussion, no claim about paraphrase robustness, and no statement about the legal or ethical ground. The plan scopes to the source's stated surface and does not invent any of those.

## Objective

Ship an open-source tool with two surfaces — an agent skill callable from Claude and a stdlib HTTP service — that strips the deterministic marks the source names (invisible Unicode characters and C2PA / EXIF / XMP metadata) from files the user owns, and that attempts, on a best-effort basis, the statistical text marks in the four families the source names (Claude, Gemini-SynthID, OpenAI, Kirchenbauer and keyed-Gumbel class). The HTTP service must be implementable on Python's standard library so the dependency surface stays small, and the agent skill must follow the conventions a Claude skill is expected to follow. The objective includes preserving the author's own best-effort qualifier on the statistical class throughout the documentation so no user is led to expect guarantees the tool does not provide.

## Target Users

- Authors and developers who want to remove the deterministic invisible-Unicode and metadata marks from files they own before publishing.
- Self-hosting operators who need an HTTP endpoint that strips those marks on the way out, and who want the endpoint to be implementable on Python standard library so the deployment stays small.
- Creators concerned about a third-party watermark detector re-identifying their text, who understand the statistical-removal class is best-effort rather than guaranteed.
- Claude agent users who want to invoke the removal as a skill rather than as a hand-rolled script, so the agent has a documented surface to call.
- Operators and reviewers who want to read the small dependency surface of a stdlib HTTP service rather than trust a heavier framework.
- Privacy-focused users who specifically want to control which metadata fields leave their machine, and who would rather run a local tool than upload to a third-party service.
- Researchers documenting the realistic state of LLM watermark removal, who can use the tool as a reference for what best-effort looks like in practice.

## MVP Scope

- A Python stdlib HTTP service exposing endpoints for each of the three deterministic classes: invisible Unicode, C2PA metadata, EXIF/XMP metadata.
- An invisible-Unicode stripper that operates on common file types (text, markdown, source code) and that lists which codepoints were removed so the user can audit the change.
- A C2PA stripper that removes the manifest and any embedded assertion store from supported image and document formats.
- An EXIF/XMP stripper that operates on JPEG, PNG and TIFF, with a configurable allowlist of fields the user wants to keep.
- A best-effort statistical-text stripper that targets the four families named in the source — Claude, Gemini-SynthID, OpenAI, Kirchenbauer and keyed-Gumbel class — with the author's own best-effort qualifier preserved in the endpoint description.
- A Claude agent skill definition that documents the same three deterministic surfaces as callable tools and exposes the best-effort statistical surface with its qualifier.
- A request and response shape that includes the count of removed items per class, so the caller can tell at a glance what changed.
- A Dockerfile so the service can be deployed the same way the rest of a self-hosting stack is.
- Documentation that places the best-effort qualifier on the statistical class in every place a user might read a success claim.

## Constraints

- The author explicitly marks the statistical text class as "best-effort"; no documentation, log line or response may state or imply a guarantee of full removal.
- The source's surface is "files you own"; the service must not advertise itself as a way to strip provenance from third-party content where the user does not have that authority.
- The HTTP surface is built on Python's stdlib, which means a small dependency footprint; any new HTTP-layer dependency has to be justified against the stdlib option.
- The Claude agent skill surface has to follow the conventions Claude skills follow; the skill definition has to be self-describing rather than relying on internal jargon.
- Invisible-Unicode removal can change the meaning of text in edge cases (for example, in identifiers that intentionally contain non-ASCII codepoints); the stripper must default to a safe mode and require an explicit flag for the broader mode.
- C2PA removal from signed documents may invalidate a downstream verifier's check; the stripper has to surface that consequence in the response rather than silently stripping.
- EXIF and XMP may carry fields the user wants to keep (for example, copyright or creator); a configurable allowlist is part of the contract, not a future option.
- The statistical text stripper's result must not claim a removal rate above what was actually attempted; "best-effort" is the operative word in every claim that touches the statistical class.
