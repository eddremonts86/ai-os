# ScriptTap – no-root Android automation with an AI script contract

## Tech Stack

Chosen for the write-once, run-deterministically loop the post describes.

- **Android automation runtime:** the on-device engine that executes scripts without root.
- **JSON script contract:** the .scripttap.json schema, documented at scripttap.com/ai, that AIs generate against.
- **ADB bridge:** a channel for coding agents (Codex, Claude) to push, run and refine scripts on connected devices.
- **Screen-aware primitives:** image and UI-element location, pixel-color change detection, screen capture and analysis.
- **Android intent surface:** shortcut, deep-link and intent exports for Tasker, MacroDroid, Automate and Samsung Routines.
- **Run logging:** detailed per-run logs that make script behavior inspectable.

## Architecture

- **Script interpreter:** parses .scripttap.json and steps commands (taps, text entry, waits, conditions) deterministically.
- **Screen perception layer:** capture pipeline plus matchers for images, UI elements and pixel regions.
- **State model:** files and variables scripts can read and write, with observed device state as the only non-determinism.
- **Bridge endpoint:** ADB-facing control so external agents can install, run and inspect scripts.
- **Export layer:** home-screen shortcuts and intent receivers that wrap scripts for other automation tools.

## Milestones

1. **M0 — Import and run.** A .scripttap.json generated by an AI imports and executes on a non-rooted test device.
2. **M1 — Screen-aware actions.** Image location, UI-element finding and pixel-color detection work end to end with capture-analyze-tap and text-entry flows.
3. **M2 — Agent loop.** The ADB bridge lets a coding agent push, run, inspect and refine a script, demonstrating the write-once loop.
4. **M3 — Interop.** Shortcut, deep-link and intent invocation verified against Tasker, MacroDroid, Automate and Samsung Routines, plus run logs at 5,000-command scale.

## Risks

- **UI fragility:** image and pixel matching breaks under theme, DPI or OS-version drift, silently changing script outcomes.
- **Contract drift:** if the schema changes without versioning, AI-generated scripts and the runtime stop agreeing.
- **Non-determinism boundary:** results depend on device state; users must be able to see in run logs why a run diverged.
- **Single-author scale claims:** 5,000-command support is one person's testing.
- **AI dependency:** the pitch assumes AI agents stay able and willing to emit the contract correctly.
