# Neo

> Product brief for the novel-writing tool launched on ProductHunt, attributed to the author of *Silo*.

## Value Proposition

A novelist can write the manuscript and manage the structure — chapters, scenes, parts, characters, places, arcs — in one tool whose design reflects the workflow of someone who has actually shipped a long, multi-volume novel. The export is something a self-publisher can hand to an editor or upload directly.

**One-liner:** A novel-writing tool built around the workflow of a novelist who has actually shipped a series.

## Target Users

| Stakeholder | Why they care |
|---|---|
| Novelists writing long-form fiction | Need chapter / scene structure on top of the prose, not a generic word processor. |
| Self-publishing and serial-release authors | Need a workflow that supports release arcs alongside the manuscript. |
| Writers managing many characters | Want character / scene / place metadata linked to the prose, not in a separate wiki. |
| Editors and beta readers (downstream) | Need a clean manuscript export, not a tool-locked format. |

The post frames the user as the author, not a co-writer or a team.

## Jobs To Be Done

1. **Functional job** — Write the manuscript in a focused surface with chapter / scene / part structure, not a flat document.
2. **Functional job** — Link characters, places, and arcs to the prose so the manuscript stays consistent across a long project.
3. **Functional job** — Export a clean manuscript (EPUB, DOCX, or PDF) suitable for an editor or for self-publishing.
4. **Emotional job** — Trust that the tool reflects a real novelist's workflow, because the author of *Silo* is behind it.

## Success Metrics

- **Activation:** start a new project → write the first chapter → export a clean manuscript, all in one session.
- **Structure coverage:** the manuscript model supports chapters, scenes, and parts; metadata for characters, places, and arcs is linkable, not freeform.
- **Export quality:** the exported manuscript is publishable as-is (or with light formatting) — not a tool-locked format.
- **Trust signal:** the project page documents the link to the author of *Silo* honestly (what the author actually built vs. endorsed vs. inspired).

## Competitive Landscape

- **General word processors** (Word, Google Docs, Pages) — flexible but ignore manuscript structure.
- **Distraction-free writing apps** (Scrivener, Ulysses, Bear) — closer to the right shape, but Scrivener is dated and desktop-only; Ulysses is Mac/iOS-only; Bear is general notes.
- **Worldbuilding tools** (World Anvil, Campfire) — great for the wiki but the manuscript itself lives elsewhere.
- **AI writing tools** — push toward generating text rather than managing a long-form project.

The project's differentiator is the explicit "from a novelist who shipped a series" framing: a tool whose design choices can be defended by a real workflow, not a generic "writing app" template.

## Risks & Open Questions

- [ ] The "from the author of Silo" framing is the headline trust signal; the project page must clarify whether the author built it, endorsed it, or inspired it, so the claim does not over-promise.
- [ ] Manuscript exports are easy to get wrong (formatting that breaks in EPUB, DOCX that loses italics). The MVP needs to test exports end-to-end, not just produce a file.
- [ ] Long projects can be very large; the editor must stay responsive at novel-scale, not just at chapter-scale.
- [ ] The post does not specify platform (web, desktop, mobile); the project page should state the supported platforms clearly.
- [ ] Scope creep into "AI writing assistant" or "publishing platform" would dilute the headline; the MVP must hold the line on novel-writing only.
