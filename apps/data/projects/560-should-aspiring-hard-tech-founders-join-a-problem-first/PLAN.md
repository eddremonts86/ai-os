# Should aspiring hard-tech founders join a problem-first or technology-first PhD lab?

## Tech Stack

Static markdown or a Notion-style document — no software to build. If interactive: a Tally form that maps the reader's interest areas to one of two lab archetypes.

## Architecture

Document-only. Three sections: (1) problem-first lab profile, (2) technology-first lab profile, (3) decision matrix. Optional: a one-page handout the reader can take to a prospective advisor.

## Milestones

M1: draft the two lab-profile sections from public sources. M2: write the decision matrix. M3: run it past two founders (one per path) for sanity-check. M4: publish as a public doc.

## Risks

Risk: advice ages quickly — hard-tech funding climate changes. Risk: reader misreads it as 'always pick problem-first', which the author explicitly notes is contested. Risk: no follow-up engagement — the doc gets read once and forgotten.
