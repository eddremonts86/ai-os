# Colrows – Compile natural language to governed SQL instead of guessing

> Auto-generated product brief. Review and refine before MVP scoping.

## Value Proposition

Colrows compiles natural-language questions to SQL against a governed semantic model rather than generating free-form SQL. The semantic model names what the warehouse exposes — tables, columns, legal joins, business rules — and the compiler is constrained to that model, so the SQL it emits cannot invent columns, join on undeclared relationships, or violate business rules because no such rule was checked.

The thesis in the title is precise. "Compile" is a deterministic translation against a known semantic model; "governed" means there is an authority above the prompt; "instead of guessing" is the explicit rejection of free-form text-to-SQL. The capture does not name the semantic-model format or the warehouse adapters, so the plan treats those as design choices to be made in MVP rather than facts to be asserted.

**One-liner:** Colrows compiles natural-language questions to SQL against a governed semantic model, so the SQL it emits is constrained by what the warehouse actually exposes rather than generated by a model that hopes for the best.

## Jobs To Be Done

1. **Functional job** — Ask a question of the warehouse in natural language and get SQL that respects the schema and the business rules.
2. **Functional job** — Govern the warehouse: declare the tables, the joins, the rules, in one place that the compiler enforces.
3. **Functional job** — Refuse questions the model cannot answer, with an explanation of why, rather than guess.
4. **Emotional job** — Trust the natural-language interface because the governance is visible and reviewable, not because the model sounds confident.
5. **Social job** — Hand a reviewed semantic model to a non-technical user and know that the questions they can ask are bounded by what the model declares.

## Success Metrics

- **Compile determinism** — share of identical question + model pairs that produce byte-identical SQL, since determinism is the load-bearing claim of "compile".
- **Refusal rate on unanswerable questions** — share of questions the compiler rejects with an explanation, since high refusal with clear reasons is the headline correctness signal.
- **False-positive SQL rate** — share of compiled SQL that runs but produces wrong results, the metric that "instead of guessing" exists to drive to zero.
- **Rule-violation incidents** — count of compiled SQL that references undeclared tables or columns or violates a business rule; the target is zero.
- **Semantic model coverage** — share of the warehouse's exposed surface that is declared in the model, since governance is incomplete when the model is incomplete.
- **Golden question pass rate** — share of golden question + expected SQL pairs the compiler passes, since the test harness is the audit trail.

## Risks & Open Questions

- [ ] Pick and publish the semantic model format, with the requirement that it is diffable and reviewable in version control.
- [ ] Define the business-rule syntax: which joins are legal, which columns are sensitive, which row-level filters are mandatory.
- [ ] Build the golden question test harness and ship it as part of the project, not as a separate QA tool.
- [ ] Pick the warehouse adapters for MVP and document the unsupported adapters honestly.
- [ ] Build the refusal path so unanswerable questions are refused with an explanation rather than answered with a guess.
- [ ] Measure compile determinism and publish the number, since determinism is the load-bearing claim.
- [ ] Decide the operator surface (CLI, web, or both) and the read-only default, so the system cannot accidentally become a write tool.
