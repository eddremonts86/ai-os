# An anonymous, no-signup alert app – try it live with GitHub incidents

## Value Proposition

One-way alerts without an app download, a phone number or an account. Organizations broadcast updates to groups; individuals create personal alerts or join groups anonymously and pause, resume or leave with one tap. Built by someone tired of scam texts, forced app installs and group-chat chaos — the live demo includes a GitHub Incidents group that alerts whenever GitHub's status page reports an incident, running on the same infrastructure customers use.

**One-liner:** A no-signup, no-PII alert app plus a SaaS broadcast platform, proven live with GitHub status incidents.

## Target Users

| Stakeholder | Why they care |
|---|---|
| Coaches and organizers | Gym-change and event updates reach everyone as alerts instead of drowning in group chat or unchecked email. |
| Privacy-conscious individuals | Alerts and reminders with no account, no phone number and no PII collected. |
| Operations teams | A status-page incident alert group without building any polling infrastructure. |

The author describes his own problems with scam texts, app-download demands and sports-team messaging as the seed cases.

## Jobs To Be Done

1. **Functional job** — Broadcast a one-way message to a defined group of people.

2. **Functional job** — Receive alerts about a service (like GitHub incidents) without installing anything or giving up personal data.

3. **Functional job** — Manage membership anonymously: join a group, pause, resume or leave in one tap.

4. **Emotional job** — Reclaim the notification channel: only alerts you chose, from groups you joined, with no scam-text noise.

## Success Metrics

- **Group delivery:** broadcast alerts reach every member of a group on production infrastructure (the demo groups prove it live).
- **Anonymity:** zero signup, zero phone number, zero PII collected or stored for personal users.
- **Control:** pause, resume and leave each take one tap.
- **Live proof:** GitHub Incidents and Indie Hackers Case Studies run on the same infra customers use.

The stated differentiator is the identity model: no signup, no phone number, no PII, in a space where the author's stated pain is being forced to download apps just to receive notifications.

## Risks & Open Questions

- [ ] The capture is a URL plus the author's comment; there is no usage or revenue evidence beyond the two live demo groups.
- [ ] Anonymity limits engagement channels: with no account and no PII, there is no email or phone fallback if delivery fails.
- [ ] Broadcast platforms live or die on sender quality; the author's own story starts with hating spam, so anti-abuse matters more here than elsewhere.
- [ ] One-way only is a constraint some organizations will chafe at when they need confirmation or replies.
- [ ] No pricing stated leaves the SaaS economics entirely unknown.
