// what is it

The answer to "I just got a new Mac. How do I get my AI setup back?"

Most devs who use AI assistants daily end up with skills scattered across ~/.claude/, ~/.codex/, MCP servers hardcoded with no version control, and the Spec→Plan→Execute→Verify loop living only in their head. AI-OS puts all of it in one git repo, and keeps the products it builds out of it once they outgrow it.

METHOD

Spec → Verifier → Environment

Karpathy's framework as recurring workflows, hard rule-sets, and verifier gates applied after every task. One active Spec at a time; nothing ships without a runtime check.

spec→plan→execute→verify
SKILLS

One source of truth, every CLI

14 required superpowers + 163 curated & vendored skills (14 of them hand-picked from ECC), symlinked into Claude Code, Codex, Gemini, Antigravity, Hermes & MiniMax. Project-specific skills stay in their own repos.

CONFIG

MCP + dotfiles as code

7 MCP servers as declarative YAML, generated at install — including a local graph memory and semantic code search. zsh, Warp, Brewfile & git config versioned in the same repo.

BOUNDARY

Framework above, products below

Everything above apps/ is the operating system. What it builds lives under apps/ until it needs its own release cadence, then it splits out.

Every substantial task runs the same loop.

Spec quality first, verifier passes second, runtime evidence third. No "it builds, ship it."

Spec

Define the objective

For work over ~2 hours or across repos: one active spec — objective, acceptance criteria, non-goals, risks.

Plan

Break into steps

Small, checkable steps, dispatched in parallel when independent.

Execute

Step by step

Verify after each step. Sub-agents self-report; you check the handles.

Verify

Gates per task

Quality checklist, self-critique, source-check. Evidence before "done".

// runs itself

It looks after itself, so you only hear about it when something breaks.

Health checks, encrypted backups and a secrets guard run on a schedule and on every push. Each one is a single ai-os command you can also run by hand.

Health, twice a day

15 functional checks at 09:30 and 15:30: graph memory, MCP servers, CI, secrets, backups. A desktop notification if one fails. ai-os health

Encrypted backups, your repo

Memory graph, secrets file and Claude memory, daily and restore-checked. AES-256-GCM copies go to iCloud and, only if you name one, your own private GitHub repo. Each machine gets its own branch. Off with one command. ai-os backup

Secrets never pushed

The pre-push hook refuses any commit that contains a value from your .env. An audit scans every local repo's history and reports key names, never values. ai-os secrets

A gate on every push

Syntax, skill frontmatter, unit tests, install dry-runs and published numbers, checked on the exact commit being pushed. About ten seconds. setup/hooks/pre-push

Updates that roll back

Nothing upgrades on its own. When you bump one component, its health checks run and the change is reverted automatically if they fail. ai-os update

A skill budget

Every skill's description costs tokens in every session. Lint keeps the catalogue near 10K tokens, flags near-duplicates and checks typical requests still reach the right skill. ai-os skills

// install

One command. Verify.

Pick your OS. Copy the block. Most of the 30–60 min first install is just downloading packages.

# 1. bootstrap (clones + runs the Mac installer)
npx @edd_remonts/create-ai-os
cd ai-os

# 2. verify (20 health-check sections)
bash setup/verify.sh
ai-os health

# 3. off-site backups to your own private repo (optional)
ai-os backup --github-repo you/ai-os-backups
# PowerShell as Admin: bootstrap (clones + runs the Windows installer)
npx @edd_remonts/create-ai-os
cd ai-os

powershell -ExecutionPolicy Bypass -File .\setup\verify-windows.ps1
# Debian / Ubuntu: same bootstrap, cross-platform installer
npx @edd_remonts/create-ai-os
cd ai-os

bash setup/verify.sh

Prerequisites

  • Apple Silicon / Intel Mac, Windows 10-11, or Linux
  • git, curl and an internet connection
  • ~30–60 min for the first run (mostly downloads)

Optional layers

  • vendor/ecc/README.md: how to vendor more ECC skills from upstream
  • setup/install-claude-tools.sh: 12 more claude.tools / gstack skills
  • DRY_RUN=1: simulate without touching your machine
