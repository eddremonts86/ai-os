# Provenance and scope

These skills were distilled from an operational guide written on 2026-08-05, itself derived from:

- **Primary source:** Olly Rosewell, *How I Design SaaS That Looks EXPENSIVE (beginner friendly / UI
  guide)* — <https://www.youtube.com/watch?v=9d5fRVDkzRI> (published 2026-08-01).
  Its public description confirms it covers: AI design patterns that make an app look like slop
  (emojis, colour, repeated data), durable UI laws, onboarding, speed, landing pages, and the
  screenshot workflow.
- **Secondary source, same author:** *How I Design Beautiful SaaS (Frontend & UI Guide)* —
  <https://www.youtube.com/watch?v=LZ_FFvr1DZE> (2025). Its public chapters cover clarity, jobs to be
  done, feedback loops and analytics, consistency, visual hierarchy, linear vs exploratory
  onboarding, speed as aesthetic, UI as identity, progress and value tracking, confirmation layers.

## Honesty caveat — read before attributing

The session that produced the source guide **only had the transcript of the pre-roll advertisement**,
not the video body. Consequently the guide, and therefore these skills:

- Contain **no literal quotations** from the author and **no timestamps**.
- Mix three provenance levels, which the original guide tagged explicitly:
  - **[A]** confirmed by the current video's public description/summary
  - **[B]** developed by the same author in the earlier guide
  - **[C]** operational application written by the guide's author, not by Rosewell
- Should be treated as a **grounded operational framework**, not a transcript.

When citing this material to a user or in a document, say "distilled from Olly Rosewell's SaaS UI
guides plus applied practice" — do not claim any specific sentence is his.

## What was dropped in the distillation

The source guide also contained a 30-day calendar, a weekly product-quality meeting agenda, a
