# Master checklists

Run the relevant ones per flow. Each unchecked box is a candidate finding.

## Slop removal

- [ ] No emojis as controls or critical icons
- [ ] No colours without semantic or brand function
- [ ] No gradients or glows applied by default
- [ ] No glassmorphism that reduces legibility
- [ ] No cards inside cards without a structural reason
- [ ] No invented or duplicated data
- [ ] No decorative charts
- [ ] No badges that change no decision
- [ ] No multiple primary CTAs
- [ ] No mixed icon families
- [ ] No entrance animation on every element
- [ ] No generic copy that could belong to any SaaS

## Clarity and hierarchy

- [ ] The user understands where they are
- [ ] They understand what changed
- [ ] They recognise what to do next
- [ ] Critical information appears first
- [ ] Advanced configuration is on demand
- [ ] Navigation reflects jobs, not the internal team structure
- [ ] Relevant filters are available without dominating the screen
- [ ] CTAs describe their consequence

## Data and trust

- [ ] Every KPI has a definition
- [ ] Every value has a unit
- [ ] Every comparison has a stated base
- [ ] Freshness is dated
- [ ] Source is visible when it matters
- [ ] Data quality or availability is indicated
- [ ] Errors are not rendered as zero
- [ ] Estimates are distinguished from observed data
- [ ] Sensitive actions leave an audit trail

## Onboarding

- [ ] An activation event is defined
- [ ] Onboarding leads to that event
- [ ] Only necessary information is requested
- [ ] Progress is saved
- [ ] Optional steps can be skipped
- [ ] Permission requests are explained
- [ ] Sample data exists where it helps demonstrate value
- [ ] The user can return to the checklist
- [ ] Abandonment and time-to-value are measured
- [ ] The first in-product message continues the landing promise

## Speed

- [ ] No critical route shows a blank screen
- [ ] Every action gets immediate feedback
- [ ] Loading preserves layout structure
- [ ] Long operations show staged status
- [ ] Errors allow retry or recovery
- [ ] Form data is never lost
- [ ] Requests are deduplicated
- [ ] Large lists paginate or virtualise where appropriate
- [ ] Performance budgets exist
- [ ] The team reviews percentiles, not only averages

## System and identity

- [ ] Colour, spacing, radius, shadow and typography come from tokens
- [ ] Canonical components are documented
- [ ] Exceptions have an owner and a review date
- [ ] Terminology is stable
- [ ] Brand voice appears at useful moments
- [ ] Marketing and product share promise and language
- [ ] Identity does not depend on excess decoration
- [ ] Patterns feel proprietary without sacrificing familiarity
